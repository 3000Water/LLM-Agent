# 自动合成机关工作总结——技术思路

## 一、起点：先理解文档，再设计系统

整个工程的第一步是**把所有相关文档转换为可处理的格式**。源文件混合了 `.docx`、`.doc`（旧二进制格式）、`.pdf` 三种格式，使用 `mammoth`（处理 docx）和 `PyMuPDF`（处理 pdf）将它们批量转换为 Markdown，并设计了格式回退和断点续传机制，确保所有文件都能被后续流程消费。

这一步看似工具性，实际上是整个系统的数据基础——格式转换质量直接决定后续内容提取的上限。

---

## 二、核心前提：人工分析现有文档的对应关系

**在写任何一行代码之前，先做了最重要的一件事：手工阅读并分析现有部门工作总结与 5 份个人总结之间的映射关系。**

### 2.1 映射关系：多对多、非对称

| 部门总结章节 | 主要贡献人 | 映射特征 |
|---|---|---|
| 主题教育 | C（主）、Z（辅） | C 的第一节几乎逐段提炼 |
| 一流学科培优 | L（主）、C（辅） | L 写框架，C 写执行细节 |
| 学科布局优化 | X（独占） | X 第 1 节是原始素材 |
| 双一流建设 | L + C + X | 同一事件（中期自评）被三人描述，需去重合并 |
| 优势学科四期 | C（主）、X（辅） | — |
| 苏州校区 | L + X | 一人写规划文稿，一人写论证工作 |
| 国际评估 | Z（独占） | Z 的第 2 节原文压缩 |
| 学术委员会 | S（独占） | S 的第 3 节完整对应 |
| 专家组织 | X + C | X 写委员推荐，C 写长三角联盟 |

### 2.2 文体转换规律

部门总结不是个人总结的简单拼接，而是三层变换：

1. **去个人化**："我完成了…" → "办公室组织完成…"
2. **提升抽象层次**：执行细节（"2月召开"、"填写了xx表格"）→ 项目成果（"组织完成…工作"）
3. **补充政策背景**：个人总结里不存在的宏观表述（"对接国家十四五规划"、"协同卓越研究计划"）

### 2.3 分析的工程价值

这一人工分析直接回答了三个后续设计问题：
- 应该设几个节、每节边界在哪里
- 每节对应哪些人的哪些内容
- 哪些内容最容易跨节溢出（高风险点）

**没有这一步，后面的 Prompt 工程就是盲目的。**

## 三、框架设计：将分析结论转化为工程约束

基于人工分析，将章节框架固化为 `config.py` 中的 9 个 `SECTION` 对象，每个对象包含四个维度：

```python
{
    "key":         # 用于 JSON 提取的唯一标识符
    "title":       # 最终输出的章节标题（与原文一致）
    "description": # 来自：分析出的该节涵盖工作范围
    "exclude":     # 来自：分析出的高频跨节溢出风险点（排他说明）
    "word_range":  # 来自：原始部门总结各节实际字数区间
}
```

其中 `exclude`（排他说明）是最关键的设计，它来源于第一轮运行失败后的诊断——第一版没有排他说明，导致"双一流建设"节从 525 字膨胀至 746 字，省优势学科四期、苏州校区等本属别节的内容全部溢入。这不是 LLM 的问题，而是分类定义本身存在歧义。

## 四、流程设计：两阶段 Pipeline

```
个人总结 × N
    │
    ▼  【阶段一：结构化提取】  每人 1 次 LLM 调用
    │  输入：个人总结全文
    │  输出：{职能维度 → [具体事项列表]}  (JSON)
    │  目标：捞全、不失真、精准分类
    │
    ▼  【聚合】  纯代码，无 LLM
    │  按维度合并各人结果，标注来源标签 [C]/[L]/...
    │  中间产物写入 aggregated.json（人工可审查的质量卡点）
    │
    ▼  【阶段二：逐节撰写】  每节 1 次 LLM 调用
    │  输入：当前节要点列表 + 其他节标题（防溢出上下文）
    │  输出：正文段落
    │  目标：文风统一、层次适当、不越界
    │
    ▼  【压缩校验】  按需触发
    │  超出字数上限 × 1.15 则触发压缩调用
    │
    ▼  【组装输出】
       格式由配置控制（公文粗体 / Markdown H2）
```

### 为什么是两阶段而不是一次性生成？

| 方案 | 问题 |
|---|---|
| 一次性：全部原文 → 直接生成总结 | 内容容易遗漏；结构失控；无法调试；上下文过长 |
| 两阶段：先提取再撰写 | 职责分离；中间层可审查；失败可重跑单阶段 |

两阶段的本质是**分离"理解"和"生成"**：提取阶段专注捞全、不失真；撰写阶段专注文风、不越界。中间的 JSON 形成可审查的质量卡点。

## 五、Prompt 工程的关键决策

### 决策一：排他定义（最重要）

仅告诉 LLM「这节写什么」不够，必须同时告诉它「这节不写什么」。

```
# 提取 Prompt 中每个维度的写法：
- "双一流建设"：双一流中期自评、亮点工程优化、绩效监控、系统建设
  【不含】省优势学科四期（专属另一节）；国际排名；苏州校区；学术委员会
```

效果：第4节偏差从 **+221 字**降至 **+13 字**。

### 决策二：抽象层次约束

部门总结与个人总结的核心差异不是内容，而是粒度。撰写 Prompt 中明确要求：

> 保持**部门级抽象层次**：描述重要工作项目和成效，不写具体会议时间（如"2月"）、数据库名称（如 InCites）、个人操作步骤等执行细节。如果字数超出上限，优先删减最细粒度的执行内容。

### 决策三：注入完整节列表防溢出

撰写 Prompt 中注入其他 8 节的简短摘要，让 LLM 在写作时有明确的边界感：

```
本节是9节工作总结的第4节。其余各节分别负责：
  第1节「主题教育」：党支部活动、主题教育成效…
  第2节「一流学科培优」：培优行动方案、教育部考察…
  ...（当前节以外的其余8节）
请确保本节内容不与其他节重叠。
```

### 决策四：温度参数分层

| 阶段 | 温度 | 原因 |
|---|---|---|
| 提取（JSON 分类） | 0.2 | 低温减少分类发散，需要确定性 |
| 撰写（正文段落） | 0.6 | 中温保持文风自然流畅 |
| 压缩（内容精简） | 0.3 | 低温减少内容改动，只精简不重写 |

### 决策五：去重交给撰写阶段

聚合时刻意保留来源标签（`[C] 事项`、`[L] 事项`），不在代码层做预处理去重，而是在撰写 Prompt 中要求"相似内容只写一次"。理由：代码层字符串去重会误删同一事件的不同侧面描述；LLM 能更准确地识别语义重复。

## 六、工程健壮性设计

| 设计 | 作用 |
|---|---|
| 提取结果实时写缓存 | API 中途失败可从断点恢复，不重跑已完成的部分 |
| `--skip-extract` 参数 | 调整撰写 Prompt 后只重跑写作阶段，节省时间和费用 |
| 聚合结果保存为 JSON | 人工可审查每节的原始要点，在生成前发现分类错误 |
| 字数超标自动触发压缩 | 兜底机制，不依赖 LLM 自觉遵守字数约束 |
| 格式配置化 | `SECTION_HEADING_STYLE = "bold"/"h2"` 一个开关适配不同场景 |

## 七、迭代优化：数据驱动的诊断与改进

第一版运行后，通过**定量对比**（逐节字数统计）和**定性对比**（逐段 diff）系统诊断问题：

### 问题诊断

| 问题 | 发现方式 | 根因 |
|---|---|---|
| 内容跨节溢出（第4节 +221 字） | 字数统计 | 维度定义无排他说明 |
| 抽象层次偏低（执行细节入文） | 逐段 diff | 撰写 Prompt 无层次约束 |
| 关键内容丢失（文件名、日期缺失） | 逐段 diff | 提取 Prompt 未强调"保留具体事实" |
| 输出格式不一致（H2 vs 粗体） | 直接观察 | 格式硬编码 |

### 改进效果

| 章节 | 原始 | v1（改前） | v2（改后） |
|---|---|---|---|
| 主题教育 | 294 | +156 | +96 ↓ |
| 一流学科培优 | 262 | +214 | +86 ↓ |
| **双一流建设** | **525** | **+221** | **+13 ↓↓** |
| 优势学科四期 | 400 | −55 | +28（内容更完整）|
| **总计** | **3065** | **+796** | **+428 ↓** |

## 八、方法论结论

### 这套方法的本质

这不是"让 LLM 写作文"的工程，而是**人工分析驱动 AI 流程设计**的工程。

| 贡献者 | 负责的判断 |
|---|---|
| **人工分析** | 章节框架定义、排他边界识别、抽象层次判断、质量基准 |
| **LLM** | 大规模文本提取的执行效率、文风统一性、语义去重与合并 |

分工边界清晰：凡是需要「领域判断」的地方由人工分析前置固化；凡是需要「大规模执行」的地方交给 LLM。

### 可推广的通用模式

核心模式：**结构化提取 → 重组聚合 → 风格化生成**，适用于所有"多源输入、固定框架输出"的文档合成场景：

- 多份调研报告 → 综合报告
- 多部门汇报材料 → 领导汇报稿
- 项目周报 × N 周 → 月度/季度总结

关键变量只有两个：**章节框架的定义精度**（越精确，溢出越少）和**输入文本的信息密度**（密度越高，提取阶段越重要）。两者都依赖对目标文档的深度人工分析，而非纯粹依靠 LLM 自主理解。
