## 📖 梳理过程回顾（仅供参考）

### 那么梳理是怎么做的？

#### 第一步：粗梳理（高层结构）
**重点问题**: 成品文件有几个最大的章节？它们叫什么？

**做法**: 
1. 打开南京大学十四五规划.md或.pdf
2. 识别顶级章节：发展基础、发展环境、指导方针和主要目标、建设任务、组织与保障
3. 计数：共5个

**输出**: 成品的5层结构图

#### 第二步：生成映射表（中层）
**重点问题**: 每个最大章节分别由哪些部门规划贡献内容？

**做法**:
1. 逐个分析19份部门规划
2. 对每份部门规划，确定它对应成品的哪个最大章节（可能多个）
3. 估计占比
4. 记录在表格中

**输出**: full_mapping_relationships.csv 的粗行（单层映射）

#### 第三步：细梳理（组织内容）
**重点问题**: 成品每个章节下的子标题分别来自哪些部门？

**做法**：
1. 针对"发展基础"，识别11个子标题。对每个子标题，查找贡献源文件
2. 针对"建设任务"，识别10个小类。对每个小类，分配贡献源文件和占比
3. 对其他章节，类似处理

**输出**: full_mapping_relationships.csv 的全部行（双层映射）

#### 第四步：结构化存储
**重点问题**: 如何让代码能用这个映射关系？

**做法**:
1. 将映射关系转为JSON结构（section中心）
2. 为每个section记录contributing_sources数组
3. 为每个source记录file、weight等

**输出**: mapping_detail.json

#### 第五步：配置生成
**重点问题**: 系统应该怎么处理这5个章节？

**做法**:
1. 为每个章节定义SECTION记录
2. 设置id、title、key、description、exclude、word_range等参数

**输出**: config.py

## 🔑 关键词解释

### 什么是"粗梳理"？
从部门规划出发，看它对应成品的哪个**最大章节**。  
特点：快速、高层、一对一或一对多

### 什么是"细梳理"？
从成品章节出发，看它对应哪些**具体源文件及占比**。  
特点：详细、底层、多对一

### 什么是"映射方向"？
**目的文件中心** (current):
```
发展基础 
├─ 党的全面领导 ← 党委统战部(85%) + 纪委(15%)
├─ 人才培养成效 ← 本科生院(90%) + 研究生院(10%)
└─ ...
```

**来源文件中心** (X 不推荐):
```
党委统战部规划
├─ 对应 发展基础 (85%)
├─ 对应 建设任务 (15%)
└─ ...
```

为什么选目的中心？——更清晰，代码实现更直接。

### 什么是"占比"和"权重"？
**占比** (percentage): 人工估计，显示在CSV中（"占比70%"）  
**权重** (weight): 结构化数值，存在JSON中（0.70）

### 什么是"占大篇幅"和"作为补充"？
- **占大篇幅** (≥80%): 主要贡献者
- **作为补充** (<10%): 辅助贡献者
- **介于两者**: 重要贡献者

## 🎯 梳理对代码改造的约束

### 对prompts.py的约束
- 提示词要明确"5个SECTIONS"而非"9个工作总结"
- exclude字段必须明确列出各章节排除的内容类型

### 对extractor.py的约束
- 必须支持多源提取（某小类从多个源文件提取）
- 必须根据mapping_detail.json进行"映射感知提取"
- 降级方案：如果mapping_detail.json不存在，使用全量源文件

### 对config.py的约束（已满足）
- SECTIONS必须恰好5个
- 必须包含MAPPING_DETAIL_FILE配置
- description字段必须列出所有对应的小标题

## 📞 常见问题

**Q**: 梳理过程中的决策是最优的吗？  
**A**: 不一定。梳理是基于当前理解的最佳估计。如发现不合理，可调整CSV和JSON后重新运行。

**Q**: 为什么某个部门规划被分配到多个小类？  
**A**: 因为该部门规划涉及多个方面（如队伍建设涉及"队伍建设新机制"和"学科建设"等）。这在mapping_detail.json中会有多个条目。

**Q**: 如果我想增加/删除某个源文件？  
**A**: 
1. 编辑 full_mapping_relationships.csv
2. 更新 mapping_detail.json  
3. 运行验证脚本
4. 重新运行synthesis

**Q**: 梳理结果能否自动生成？  
**A**: 不能。梳理需要人工专业判断（看规划内容、判断属于哪个小类等）。JSON等结构化部分可半自动生成，但源映射必须人工。
