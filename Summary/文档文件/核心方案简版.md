# 核心总结：如何用 Mapping 环节实现小章节汇总

## 🎯 问题陈述

你遇到的问题：
- ❌ config.py 中 5 个大章节的 SECTIONS 有了
- ❌ 但小章节缺少细节描述（发展基础 11 个、建设任务 10 个）
- ✅ 而 full_mapping_relationships.csv 已有粒度到小章节的映射

**本质问题**：数据结构不匹配
- CSV 里是"小章节 → 源文件"的映射
- 但 config.py 只有"大章节"的定义
- **缺少中间层**来桥接这两者

---

## 💡 解决方案核心思路

### 原理图

```
旧流程（大章节粒度）：
部处文档 → 提取（大章节分类） → 聚合 → 撰写（整章节一次生成） → 输出

新流程（添加Mapping → 小章节粒度）：
部处文档 → 提取（按小章节映射分类） → 聚合（按小章节汇聚） → 撰写（逐小章节生成） → 输出
                                    ↑
                              【新增Mapping层】
```

### 关键改动

| 环节 | 改前 | 改后 |
|-----|------|------|
| **配置** | 只有 5 个大章节 | 大章节 + 21 个小章节映射（config_mapping.json） |
| **提取** | 按大章节分类 | **按小章节映射分类**（JSON key 是小章节 key） |
| **聚合** | 直接拼接 | **按小章节聚合**多部门内容 |
| **撰写** | 整个大章节一次性生成 | **逐小章节生成**，然后拼接 |

## 📈 改造的主流程

```python
# synthesize_with_mapping.py

# ━━ 第一阶段：提取 ━━
# 改造 extractor.py 的 Prompt 和 JSON 输出结构
extractor = Extractor(config_mapping_path)
all_extracts = {}
for dept_doc in department_documents:
    extracts = extractor.extract(doc_text, dept_name)
    # ✨ 改变：返回的 JSON 以小章节 key 【分组】
    # {
    #   "development_foundation": {
    #     "subsection_abc": [...],
    #     "subsection_def": [...]
    #   }
    # }
    all_extracts[dept_name] = extracts

# ━━ 第二阶段：聚合（新增）━━
aggregator = MappingAggregator(config_mapping_path)
aggregated_all = aggregator.aggregate_all_sections(all_extracts)
# ✨ 新增：中间产物：aggregated_by_mapping.json
# {
#   "development_foundation": {
#     "subsection_abc": {
#       "contents": [...],  ← 多个部处文档的聚合内容
#       "source_distribution": {...}
#     }
#   }
# }

# ━━ 第三阶段：撰写（改造）━━
# 改造 writer.py：不再一次性写整章节，而是逐小章节
writer = Writer(config_mapping_path)
all_subsection_texts = {}
for section_key, section_agg in aggregated_all['sections'].items():
    for ss_key, ss_agg in section_agg['subsections'].items():
        # ✨ 改变：逐小章节生成
        text = writer.write_subsection(section, subsection, ss_agg)
        all_subsection_texts[ss_key] = text

# ━━ 第四阶段：拼接 ━━
# 将小章节文本按大章节结构拼接
for section in config_mapping['sections']:
    subsection_texts = [
        all_subsection_texts[ss['key']]
        for ss in section['subsections']
    ]
    section_output = section['title'] + "\n" + join(subsection_texts)

# ━━ 第五阶段：输出 ━━
final_output = join(all_section_outputs)
save(output_path, final_output)
```

## 📌 关键设计决策的解释

### 为什么要有单独的 Mapping 层？

**旧问题**：config.py 和 full_mapping_relationships.csv 之间没有联系
```
config.py        CSV 文件        实际 Prompt
(5 大章节)   vs   (小章节映射)  vs  (什么都没有)
    ↓                              ↓
   不用          无连接           LLM 不知道小章节
```

**新方案**：config_mapping.json 作为中间桥梁
```
config_mapping.json（21 个小章节的结构化映射）
    ↓                    ↓                    ↓
Extractor Prompt    Aggregator 逻辑      Writer Prompt
(按小章节提取)      (按小章节聚合)        (按小章节撰写)
```

### 为什么逐小章节生成而不是整章节一次性？

**问题**：如果大章节分配 1000 字，LLM 容易
- 在某个小章节堆砌细节，超过预算
- 难以精确控制每个子主题的篇幅

**解决**：每个小章节单独配置字数
```python
subsection_words = total_chapter_words / number_of_subsections
write_subsection(..., target_words=subsection_words)  # 独立约束
```

结果：
- 每个小章节 100 字左右（11 个 = 1100 字，在容差内）
- 质量均衡，易于调整
