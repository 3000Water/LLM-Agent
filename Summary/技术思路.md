# 技术思路：部处「十四五」规划汇总项目

> **文档定位**：本项目技术路线、问题与对策以本文档为**唯一维护入口**；其他文件名若存在历史版本说明，请以本文为准。

---

## 1. 项目背景与目标

本项目由旧版「办公室年度工作总结合成」改造而来，当前目标是：

- 面向各部处「十四五」规划材料，完成结构化提取、聚合与统一成文；
- 输出学校层面的规划汇总文本，而非单一部门年度总结；
- 在关键大章节（发展基础、建设任务）引入子章节（Mapping）粒度，提升边界清晰度与可解释性。

**关键文件**：主流程 `synthesize/synthesize_summary.py`；章节与字数 `synthesize/config.py`；子章节映射 `synthesize/config_mapping.json`（可由 `synthesize/mapping/mapping_manager.py` 从 CSV 生成）。

---

## 2. 核心思路

### 2.1 从「工作总结」到「规划汇总」

- 旧口径侧重年度完成情况；新口径按规划五章：发展基础、发展环境、方针目标、建设任务、组织保障。
- 提示词、聚合结构、写作主语与文风统一为「学校规划文本」语境。

### 2.2 子章节（Mapping）层

- 大章节内再按 `config_mapping.json` 的小节 key 提取与聚合，便于控制混写与篇幅。
- 提取结果可在 `extracted.json` 中以 `【subsection_key｜小节标题】要点` 形式展示，便于人工核对映射。

---

## 3. 实现框架与数据流

### 3.1 提取（`synthesize/extractor.py`）

- **主提取**：单文档 → 五章 JSON。
- **子章节提取**：按映射对指定大章调用 LLM，输出 `{subsection_key: [要点…]}`。
- **稳定性**：解析失败时可走「LLM 将输出修复为严格 JSON」；原始/修复片段可落盘至 `debug_subsection_raw/`，便于排查。
- **标签回流**：子章节要点可合并写回对应大章字段，便于在 `extracted.json` 中直接看到小节归属。

### 3.2 聚合（`synthesize/synthesize_summary.py`）

- 普通章节：多部门要点列表合并，并带来源前缀。
- 有子章节章节：按 `{大章 key → 小节 key → 要点列表}` 聚合。

### 3.3 写作（`synthesize/writer.py`）

- 普通章节：一次 LLM 成段。
- **有子章节章节**：按小节顺序多次调用 LLM，再拼接成整章；超字数触发压缩；可选全文引言。
- **重要**：`config.py` 中通常只设 `has_subsections=True`，**小节列表以 `config_mapping.json` 为准**；写作逻辑须从映射文件加载 `subsections` 定义后再逐节撰写，否则会出现「聚合有数据、成品章节为空」。

### 3.4 映射生成（`synthesize/mapping/mapping_manager.py`）

- 大章 `section_id` / `section_key` / `section_title` 以 `config.py` 的 `SECTIONS` 为基准生成，与主流程一致。
- 支持标题归一化；脚本可直接运行（已处理项目根路径，避免 `ModuleNotFoundError: synthesize`）。

## 4. 中间产物（`output/intermediate/`）

| 文件 | 作用 |
|------|------|
| `extracted.json` | 单文档主提取结果；含子章节标签时可快速核对 |
| `subsection_extracted.json` | 子章节结构化提取 |
| `aggregated.json` | 多部门聚合后的要点（含子章节结构） |
| `written.json` / `written_final.json` | 撰写结果（压缩前/后） |
| `debug_subsection_raw/` | 模型原始或修复过程中的文本，便于排查解析与格式问题 |

## 5. 实施中的问题与对策（并列主题）

以下问题在项目中均出现过，**彼此并列**；其中「模型返回格式 / JSON 解析」只是 **5.1 稳定性** 中的一部分，**不作为全文档唯一或最高级的问题主题**。

| 序号 | 主题 | 简要说明 |
|------|------|----------|
| 5.1 | 映射与配置一致性 | 大章 key、标题与主流程不一致导致链路错位 |
| 5.2 | 模型输出与解析稳定性 | 含空返回、非 JSON、截断 JSON 等（含原「JSON 提取」类现象） |
| 5.3 | 子章节键名与归一化 | 标题与 key 混用、需标题→key 映射 |
| 5.4 | 聚合与写作脱节 | `aggregated` 有内容但成稿章节为空 |
| 5.5 | 主提取与子章节不同步 | 主提取全空而子章节仍有要点 |

### 5.1 映射与配置不一致

- **现象**：`config_mapping.json` 与 `config.py` 的大章 key（中/英文）或章节标题不一致时，子章节提取、标签回流或写作无法对齐。
- **对策**：`mapping_manager` 以 `SECTIONS` 为准生成大章元数据；`extractor` 中对大章 key 做别名兼容；`writer` 从映射文件读取小节定义。

### 5.2 模型输出与解析稳定性（含 JSON 相关现象）

- **现象**：HTTP 成功但内容无法解析（空串、非 JSON、截断 JSON）；或主提取得到全空数组，而子章节路径仍有内容。
- **对策**：主/子提取均增加「解析失败则尝试修复为严格 JSON」；关键步骤落盘 `debug_subsection_raw/`；对源文做噪声清理（如 OLE 等残留标签）。
- **说明**：此类问题与 5.5 常同时出现，需结合 debug 文件区分「格式错误」与「模型保守输出空结构」。

### 5.3 子章节键名与归一化

- **现象**：模型返回小节「标题」而非 `subsection_key`，或 key 不一致导致归一化后丢弃有效内容。
- **对策**：标识符归一化与标题→key 映射；`extracted.json` 采用 `subsection_key｜标题` 双信息便于排查。

### 5.4 聚合有内容、写作章节为空

- **现象**：`aggregated.json` 中大章+子章有要点，最终 `部处十四五规划汇总_合成.md` 或 `written*.json` 中对应章为空或仅占位。
- **根因**：`SECTIONS` 未内嵌 `subsections` 时，若写作侧仍用 `section.get("subsections", [])` 为空列表，则**不会进入任何小节循环**，整章不调用 LLM。
- **对策**：在 `writer.py` 从 `config_mapping.json` 加载子章节列表后再逐节撰写；映射缺失时按聚合 dict 的 key 顺序兜底。

### 5.5 主提取与子章节链路不同步

- **现象**：主提取结果全空，但子章节原始或调试文件中有要点。
- **说明**：主提取与子章节为两条调用链，需分别查看 `main` 与 `subsection_*` 相关 debug；后续可考虑主提取失败时用子章节结果回填大章等策略。

## 6. 对策与实现对照（已实现）

| 第 5 节主题 | 主要落点 |
|-------------|----------|
| 5.1 映射一致 | `mapping_manager.py` 对齐 `SECTIONS`；`extractor` 大章别名 |
| 5.2 解析稳定 | `extractor.py` 中 JSON 修复兜底 + `debug_subsection_raw/` |
| 5.3 键名归一 | `extractor.py` 子章节归一化与标签格式 |
| 5.4 聚合→写作 | `writer.py` 从 `config_mapping.json` 加载 `subsections` |
| 规划口径 | `prompts.py` 中写作/压缩/引言等模板 |

**能力小结**：规划口径提示词；子章节映射与聚合；解析修复与调试落盘；子章节标签写回 `extracted.json`；映射生成与主配置对齐；写作阶段按映射加载小节列表，避免「有聚合无正文」。
